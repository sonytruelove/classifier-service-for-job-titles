# Сопоставление должностей с классификатором

## Запуск

```
pip install -r requirements.txt
python run.py
```

Результат — `results.csv` в корне проекта (рядом с папкой `data`), по всем 300 записям `data/raw_positions.csv`.

Проверить качество на эталонной выборке:

```
python evaluate.py
```

Тесты:

```
pytest --cov=. --cov-report=term-missing
```

## Как это работает

1. `normalize.py` приводит и исходное наименование, и наименование классификатора к общему виду: нижний регистр, убираются лишние пробелы, разряд/категория ("5 разряда", "1 категории"), указания на занятость ("(осн.)", "(совм.)", "(вахта)"), упоминания организаций (`АО "МостСтрой"`), раскрываются частые сокращения ("маш." → "машинист", "ЭГС" → "электрогазосварщик" и т.п.) и профессиональный жаргон, который не похож на канон по буквам, но означает то же самое ("шофер" → "водитель", "оператор автокрана" → "машинист крана автомобильного", "бульдозерист" → "машинист бульдозера"). Отдельно есть typo-коррекция для нескольких ключевых слов-ролей (оператор/крановщик/машинист/водитель/бульдозерист/производитель), чтобы опечатка в этом слове не ломала распознавание синонима.
2. `match.py` считает похожесть нормализованной строки на каждое наименование классификатора (`rapidfuzz.fuzz.token_sort_ratio`) и берёт лучшее совпадение.
3. Порог `MATCH_THRESHOLD = 0.78` подобран на `labeled_sample.csv`: при похожести ниже него результат — "нет соответствия". Записи с похожестью от 0.78 до 0.90 получают код, но помечаются "требует проверки" — здесь система обычно права, но не настолько уверенно, чтобы доверять ей автоматически. Отдельный порог `NO_MATCH_REVIEW_FLOOR = 0.60` помечает на проверку те случаи "нет соответствия", где лучший кандидат всё же не так далёк, чтобы игнорировать его совсем.

## Качество

На `labeled_sample.csv` (50 записей): **accuracy 50/50 = 100%**. Подробный отчёт — `python evaluate.py`.

## Известные ограничения

- Порог 0.60 для пометки "нет соответствия — но проверить" — компромисс. У коротких названий должностей и случайных офисных профессий (фельдшер, казначей, юрисконсульт) фоновая похожесть на записи классификатора естественным образом лежит в широком диапазоне 0.4–0.65 просто из-за общих русских словоформ. Чисто по score нельзя надёжно отличить "случайное совпадение букв" от "реального синонима, который я не знаю". Пример — "Специалист по сметам": по смыслу это, вероятно, "Сметчик", но по написанию совпадение слабое и неотличимо от шума, поэтому система его не ловит и не помечает отдельно.
- Похожая проблема на стыке опечатки и сокращения: "Эл.газосврщик" (опечатка внутри уже сжатого сокращения) не дотягивает до порога и уходит в "нет соответствия" — но с пометкой на проверку, то есть система честно сигнализирует о неуверенности, а не молчит.
- Список профессионального жаргона (синонимы вроде "шофер" → "водитель") собран вручную по тем случаям, что нашлись в `raw_positions.csv` и `labeled_sample.csv`. На новых данных с другими синонимами потребуется его пополнять.
